# Публикация сайта на GitHub Pages

Сайт статический, поэтому GitHub Pages подходит идеально — хостинг бесплатный, HTTPS включается сам.

---

## Способ 1. Через сайт GitHub, без командной строки

Подойдёт, если git не установлен или им не пользуетесь.

1. **Создайте репозиторий.** На [github.com](https://github.com) нажмите **+** → **New repository**.
   - Имя: например `alfa-expert`
   - Видимость: **Public** (на бесплатном тарифе Pages работает только с публичными)
   - Ничего не добавляйте (ни README, ни .gitignore) → **Create repository**

2. **Загрузите файлы.** На странице репозитория → **uploading an existing file**.
   Перетащите **содержимое папки `site/`** (не саму папку!): `index.html`, `404.html`, `assets/`, `uslugi/`, `sitemap.xml`, `robots.txt`, `.nojekyll` и остальные.

   > Файл `.nojekyll` обязателен. Без него GitHub пытается обработать сайт движком Jekyll и может пропустить часть файлов. Если проводник его скрывает — включите показ скрытых файлов.

   Нажмите **Commit changes**.

3. **Включите Pages.** Вкладка **Settings** → слева **Pages** → в блоке *Build and deployment*:
   - Source: **Deploy from a branch**
   - Branch: **main**, папка **/ (root)** → **Save**

4. Через 1–2 минуты обновите страницу — вверху появится адрес:
   `https://ВАШ-ЛОГИН.github.io/alfa-expert/`

При таком способе файл `.github/workflows/deploy.yml` не нужен — можете его не загружать.

## Способ 2. Через git с автосборкой (рекомендую)

Здесь `build.py` запускается на стороне GitHub при каждом изменении: правите данные в `build.py`, делаете `push` — страницы пересобираются сами, и в них подставляется правильный адрес сайта.

```bash
cd site

git init -b main
git add .
git commit -m "Сайт экспертной организации АЛЬФА"
git remote add origin https://github.com/ВАШ-ЛОГИН/alfa-expert.git
git push -u origin main
```

Затем **Settings → Pages → Source: GitHub Actions** (именно Actions, не «Deploy from a branch»).

Проверить ход сборки можно во вкладке **Actions** — зелёная галочка означает, что сайт опубликован.

Дальнейшие обновления:

```bash
python3 build.py          # проверить результат локально
git add . && git commit -m "Обновил контакты" && git push
```

## Свой домен (например, alfa-expert.ru)

1. У регистратора домена создайте DNS-записи:

   | Тип | Имя | Значение |
   |---|---|---|
   | A | @ | 185.199.108.153 |
   | A | @ | 185.199.109.153 |
   | A | @ | 185.199.110.153 |
   | A | @ | 185.199.111.153 |
   | CNAME | www | ВАШ-ЛОГИН.github.io |

2. **Settings → Pages → Custom domain** — впишите домен, нажмите **Save**.
   В репозитории появится файл `CNAME` — не удаляйте его.

3. Дождитесь проверки DNS (от нескольких минут до суток) и включите **Enforce HTTPS**.

4. В `build.py` укажите тот же домен, чтобы совпадали canonical и sitemap:
   ```python
   "site": "https://alfa-expert.ru",
   ```

## Что уже подготовлено

- `.nojekyll` — отключает обработку Jekyll
- `404.html` — оформленная страница «не найдено» в стиле сайта
- `.github/workflows/deploy.yml` — автосборка и публикация
- Все ссылки относительные — сайт работает и в подпапке (`/alfa-expert/`), и на своём домене
- `SITE_URL` — при автосборке адрес подставляется в canonical, sitemap.xml и Schema.org

## Важно: форма заявки

GitHub Pages отдаёт только статические файлы — **PHP и другие серверные обработчики там не работают**. Сейчас форма в демо-режиме: проверяет данные, но никуда их не отправляет.

Варианты для рабочей формы:

| Решение | Особенности |
|---|---|
| [Formspree](https://formspree.io) | Проще всего: меняется атрибут `action` у формы. Бесплатно ~50 заявок в месяц |
| [Getform](https://getform.io), [Web3Forms](https://web3forms.com) | Аналогично, есть приём файлов |
| Свой хостинг с PHP | Полный контроль, нужен обычный хостинг вместо Pages |

**О персональных данных.** Форма собирает ФИО, телефон и документы. При использовании зарубежного сервиса-обработчика данные уходят на серверы за пределами РФ, что затрагивает требования 152-ФЗ о локализации. Для организации, работающей с судами, надёжнее разместить обработчик на российском хостинге — этот вопрос стоит обсудить с юристом до запуска.

По этой же причине GitHub Pages разумно рассматривать как площадку для демонстрации и согласования сайта, а рабочую версию с формой размещать на обычном хостинге.
